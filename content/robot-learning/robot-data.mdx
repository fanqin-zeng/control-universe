# 机器人数据

## 搬杯子之前先读懂记录

机械臂把桌上的杯子搬到托盘。相机不断拍照，关节传感器报告姿态，控制器发出移动指令。有一天，用这些记录学出来的程序总把手伸到杯子刚才的位置：是模型太小，还是相机图像到得太晚？另一份数据在测试时误差很小，换一天摆杯子却失败：测试集里是否混入了同一次搬运的相邻画面？

这些问题在选择学习算法之前就存在。**机器人数据不是若干图片加一列数字，而是带有时间、任务和执行语义的记录。** 文件能读开，只说明存储格式通了；样本能否用来学习，还要核对机器人当时看见了什么、执行了什么、经历了什么结果。

本课沿用[学习问题与泛化](/machine-learning/learning-problem)中“训练、验证、测试分工”的概念，并用到[概率基础](/math/probability-basics)中的平均值与条件分布。这里局部定义轨迹与动作接口，不要求先掌握机器人动力学或轨迹控制律。学完应能独立完成五件事：写数据合同、按可用时间对齐、辨明动作语义、按任务需要隔离数据、生成可复查的审计清单。

全部计算使用课程自建的确定性小日志，普通 CPU 即可运行；不下载机器人数据集，不训练策略，也不把合成数据的检查结果当成真实硬件能力。

## 一次尝试怎样成为轨迹

把机械臂从复位到本次尝试结束的记录称为一条**轨迹**，也常叫 episode。一次尝试可能成功、碰撞后中止，也可能在时间预算耗尽时停止。episode 的边界表示“本次记录结束”，不必然表示任务自然完成。

一条轨迹里，第 $k$ 个决策步骤可以记为：

$$
(o_k,a_k,o_{k+1},t_k,m_k).
$$

$o_k$ 是决策时可获得的观测，例如相机图像与关节读数；$a_k$ 是动作；$o_{k+1}$ 是动作之后的观测；$t_k$ 是本步骤的时间；$m_k$ 是有效性、结束原因等元数据。观测不等于完整物理状态：被杯子遮住的物体、未测到的接触力可能影响下一步，却不在图像中。实际存储未必每行都显式存下一观测，也不一定含奖励；这里是语义清单，不是强制文件格式。

| 层级 | 至少说明什么 | 搬杯子的例子 |
|---|---|---|
| 数据集 | 版本、来源、许可、采集和处理规则 | 哪次导出、谁可使用、是否含人员影像 |
| 轨迹 | episode_id、机器人、日期、任务、场景、操作者、结果 | 同一天同一桌面的一次尝试 |
| 步骤 | 观测、动作、时间、有效掩码、结束标志 | 决策时可见图像与发出的指令 |
| 通道 | 形状、数据类型、单位、坐标系、频率、时钟来源 | 米还是毫米、相机坐标还是基座坐标 |

缺测不是零。若关节读数丢失，应保留有效掩码、时间和原因；直接补零可能制造机械臂突然回到零位的假象。当前观测有效也不代表下一观测或动作标签有效，各通道应分别标记。失败记录也不能默认删除：学示范动作时可以选取明确批准的子集，审计总尝试与部署风险时却必须保留完整分母和筛选规则。

“结束”还需拆成至少两个语义：**任务或环境的终止**，与**因为录制预算、人工中断等造成的截断**。时间耗尽不等于任务成功，紧急停止也不能当成普通成功轨迹。下一课若用动作标签学习，应先明确末步是否仍有有效动作，不能把补齐用的零动作当真标签。

## 按可用时间配对观测与动作

相机的**采集时间**表示曝光何时发生；**接收时间**表示数据何时到达决策程序。同一帧还可能经过解码和排队，工程中应以“真正可用于决策”的时间为准。若相机和控制器不是同一时钟，必须先估计时钟偏移与漂移，留下标定证据；把两台机器的时间戳直接相减没有意义。

设决策时刻是 $t_k$，某帧采集于 $t_i^{\mathrm{cap}}$，可用于决策的时刻是 $t_i^{\mathrm{avail}}$。本课的对齐规则是：只在满足下列条件的帧中，选采集时间最新的一帧。

$$
t_i^{\mathrm{avail}}\le t_k,\qquad
0\le t_k-t_i^{\mathrm{cap}}\le \Delta_{\mathrm{age}}.
$$

$\Delta_{\mathrm{age}}$ 是允许的最大观测年龄。它应由运动速度、任务误差预算与传感器性能决定，不是通用安全阈值。若没有候选帧，本规则返回无效样本；实际在线系统应按既定控制需求处理缺测，而不是偷偷借用未来帧。

教学日志的采集时间依次为 0、40、80、120 ms，可用时间依次为 10、90、85、125 ms；这是允许乱序到达的同一时钟日志。年龄预算取 60 ms，在 50、100、150、200 ms 决策时，选中的采集时间为 **0、80、120、无效**，有效的三次年龄是 **50、20、30 ms**。特别是 40 ms 采集的帧在 50 ms 决策时尚未收到；200 ms 时最新帧已经过旧。

离线用两侧帧插值会用到决策之后的信息。若研究目的本就是离线重建轨迹，可以这样做，但应与在线策略输入区分标记。监督学习的动作标签、下一观测也可以在之后才获得，**未来结果可以是目标，不能冒充当时已知的输入**。

## 动作数字必须带着执行语义

同一个向量可能表示关节位置目标、关节速度、末端位姿增量或力矩，甚至只是发送给某个低层控制器的命令。记录必须写明控制模式、维度顺序、参考坐标系、正方向、单位、持续时间和饱和范围。**命令动作不等于实际执行结果**：限幅、控制延迟和接触都可能改变运动，应另存实际状态与反馈。

假设只看末端沿一条固定直线的匀速运动，速度指令为 $v$，持续 $\Delta t$，才有：

$$
\Delta x=v\Delta t.
$$

在这个简化条件下，0.1 m/s 持续 50 ms 是 **0.005 m** 位移，持续 100 ms 是 **0.010 m**。前面的 Notebook 一并复算。若把同一个“每步位移”直接重放到另一动作频率，得到的速度会改变；若原指令其实是位置目标，上式就不适用。多维旋转增量还须声明旋转表示和组合顺序，不能把欧拉角分量随便当平移拼接。

跨机器人数据的**本体**指机器人形态和执行接口。把不同本体的动作都变成同样维数，只解决了张量形状，不证明物理含义一致。需要先确定可比较的任务空间语义、每台机器的映射、频率、可达范围和缺失通道；映射不能成立的通道应分开训练或显式标识，而不是补零后声称统一。夹爪的“开/合”编码也要核对方向，不能假定所有数据源同号。

## 先划分轨迹再生成窗口

一次搬运里的相邻画面通常很相似。随机拆帧后，一帧进入训练，下一帧进入测试，测试误差可能主要反映“见过近似画面”，而不是新一次尝试上的能力。**先声明要泛化到什么，再确定隔离单位**：

| 想回答的问题 | 至少要隔离什么 | 还不能据此声称什么 |
|---|---|---|
| 同条件下的新一次尝试 | 完整 episode | 新日期或新场景能力 |
| 换一天或换操作者 | 日期/采集会话/操作者分组 | 新机器人能力 |
| 新物体或新布置 | 物体实例/场景分组 | 任意未见环境能力 |
| 新本体迁移 | 机器人及其接口 | 跨所有机器人通用 |

训练集用于拟合；验证集用于选模型和规则；测试集保留到方案固定后检验。这里的分组也适用于三份数据两两检查。哪怕 episode_id 不同，同一天固定机位、同一物体或重复导出的近重复片段仍可能泄漏，应检查更高层来源与重复内容。

用一个简单审计量检查 episode 重合：测试轨迹集合中，有多大比例也出现在训练轨迹集合？它只检查 ID 交集，不是独立性检验。四条轨迹 A–D，各有六帧；奇偶帧切分得到训练、测试各 **12 帧**，两边的轨迹集合完全重合。不同集合对照的重合率可以是 **0、0.5、1**；这些是集合计算结果，不是模型性能提升率。

若模型输入是一段连续观测，必须先完成数据集划分，再在每条轨迹内部生成窗口。上述四条轨迹直接串起来滑动三帧窗口，会得到 **22 个窗口，其中 6 个跨轨迹**；分别在每条轨迹内部取窗，得到 **16 个有效窗口**。跨轨迹窗口会把一次复位后的画面当成上次动作的结果。短轨迹不足窗口长度时，要丢弃或采用带掩码的补齐规则，不能悄悄跨边界借帧；动作序列窗口也须遵守相同约束。

## 只用训练数据确定变换

归一化常把数值减去均值、再除以尺度。若均值和尺度从整个数据集计算，测试分布已经参与了训练流程，哪怕测试动作标签没有被直接使用，也越过了隔离边界。坐标转换用的独立标定参数可以事先固定；从样本估出的统计量则要说明来源与拟合时机。

本课按训练集总体标准差定义尺度：

$$
\mu_{\mathrm{tr}}=\frac1n\sum_{i=1}^{n}x_i,\qquad
\sigma_{\mathrm{tr}}=\sqrt{\frac1n\sum_{i=1}^{n}(x_i-\mu_{\mathrm{tr}})^2},\qquad
z=\frac{x-\mu_{\mathrm{tr}}}{\sigma_{\mathrm{tr}}}.
$$

这里分母是 $n$，不是无偏方差估计的 $n-1$。训练数据为 0、2、4、6 时，均值 **3**、尺度 **2.236068**；测试值 10、12 经同一变换得到 **3.130495、4.024922**。测试变换后不在常见范围内，本身就是分布不同的线索，不应为了好看重新用测试集居中。若混入测试值估均值，结果变成 **5.666667**。

训练通道若是常数，尺度为零；本例约定除数退回 **1** 并记录常数通道，避免除零，但不能把它理解为该通道在部署时一定无用。均值、尺度、单位、坐标变换、裁剪阈值和掩码规则均随处理版本保存。验证、测试、上线推理必须使用同一套冻结变换；仅改数据文件名并不能保证一致。

## 数据覆盖和公开资料的边界

先统计任务、物体、机器人、日期、操作者、初始条件、失败原因的覆盖，再问“还缺什么数据”。帧数多可能只是同一容易场景重复得多。成功轨迹有助于展示期望行为，失败和人工接管记录则提示策略可能进入哪些状态；它们有不同用途，应保留来源与筛选标志，不能把某个训练子集的组成当总体成功率。

例如日志记录了四次尝试，两成功、两失败。只查看保留下来的成功记录会得到 **100%**；以全部尝试为分母才是 **50% 的日志内成功比例**。两个数字都不构成部署成功概率的可靠估计：采样方案、任务难度、独立性和试验数量还没有满足统计推断要求。人类接管后的成功也不能全记在自主策略名下，应同时报告接管规则、时刻和成本。

公开资料可帮助设计接口，但要区分标准化记录与语义等价：

- [Open X-Embodiment 官方项目](https://robotics-transformer-x.github.io/)聚合不同机器人来源，用标准化数据格式支持研究。它提供跨本体学习的研究实例，不能据此推断任意动作向量都可直接拼接。使用前应核查所选来源的动作定义、采样和许可。
- [RLDS 官方 README](https://github.com/google-research/rlds)以 episode 和 step 组织序贯决策数据，并区分首步、末步与终止等字段。本课借用组织思想，不要求安装 RLDS，也不宣称合成日志符合完整 RLDS schema。其源码许可证为 Apache-2.0，具体数据的使用权还要逐来源确认。

资料复核日期为 **2026-10-24**；RLDS 仓库页面已标记归档，本文用作有版本边界的格式说明，不声称它是持续更新中的工具。本课没有复现公开项目的训练结果，也不引用排行榜数字。涉及人员画面、语音或操作身份时，还应在采集与共享规则中明确授权、访问范围及去标识方法。

## 从原日志到可交付数据

可以按以下顺序形成一份数据交付物：

1. 冻结原始文件与清单，记录来源、版本、内容哈希、许可和采集合同；处理层另存，不覆盖原始记录。
2. 核对时间单位、时钟映射、动作接口、采集/可用时间，检查乱序、重复、缺测、非有限值、越界与结束标志；不满足规则的记录进入隔离清单并保留原因。
3. 按预定泛化问题生成分组划分表，检查轨迹及更高层来源交集；冻结训练、验证、测试 ID，先划分再造窗口。
4. 只用训练记录拟合统计变换，保存参数、处理代码版本与有效掩码；固定窗口和末步处理规则。
5. 对每份数据输出总轨迹、总帧、拒收数、缺测率、动作范围、观测年龄和覆盖表；从处理结果追溯回原文件及原步骤。

哈希用于发现内容是否变化，不能证明标注正确、许可充分或物理语义一致。可复现的交付应让别人回答：“这一条训练样本来自哪次尝试？决策时输入是否已可用？使用了哪个变换版本？为何进入这个集合？”若这些问题答不清，先修数据接口比增加模型规模更有针对性，但本课不据此宣称任何策略性能提高。

本课的核心是把“可读取”推进到“可解释、可隔离、可追溯”。数据合同确定动作和观测含义；时间规则限制信息；分组规则限定评估问题；冻结变换维持训练与推理的一致性。这些是进入模仿学习之前需要具备的条件，不是闭环稳定性或安全证书。

## 习题

1. 在本课日志中，为什么 50 ms 决策不能使用 40 ms 采集的图像？200 ms 决策为何无效？如果只有采集时间而没有可用时间，能否证明在线无未来信息？
2. 某数据动作写着 0.1。需要补充哪些字段才能执行？若它明确为一维匀速速度 0.1 m/s，持续 50 ms 与 100 ms 的位移分别是多少？能否把这个换算直接用于关节位置目标？
3. 四条六帧轨迹奇偶拆分的训练/测试帧数与 episode 重合率是多少？三帧窗口直接在拼接序列取窗与逐条取窗分别得到多少窗口？为何即使无 ID 重合，也未必能证明跨日期泛化？
4. 对本课训练值 0、2、4、6 与测试值 10、12，计算训练均值、总体标准差和测试归一化值。混用所有值的均值是多少？常数通道怎样避免除零，怎样留审计记录？
5. 一批尝试两成功、两失败，只保留成功记录会得到什么比例？如何分别处理示范训练子集与总体尝试清单？录制时间耗尽与任务终止是否可写成同一个标志？

## 答案

1. 40 ms 图像到 90 ms 才可用，晚于 50 ms 决策，违反因果可用条件。200 ms 时最新采集为 120 ms，年龄超过本课 60 ms 预算，故返回无效。仅有采集时间无法排除传输与处理延迟，不能证明在线输入无泄漏；需补齐可用时间或给出保守且可验证的延迟界。
2. 至少补控制模式、通道顺序、单位、坐标系、正方向、持续时间/频率、限幅与低层控制接口。用位移等于速度乘时间，结果为 0.005 m 与 0.010 m；Notebook 1 复算。位置目标并非恒速度，不能直接套这个换算，命令也不保证实际位移。
3. 每条六帧各取一半，训练、测试各12帧，两个episode集合都是A–D，重合率1。拼接后共有24帧，三帧窗口有22个，其中6个跨边界；每条内部有4个，合计16个。ID不同仍可能共享同一天、同物体或近重复导出，要按声明的泛化轴隔离更高层来源。
4. 均值为3；平方偏差是9、1、1、9，平均为5，尺度为其平方根约2.236068。测试分别减3后除以该尺度，得到3.130495、4.024922。混合均值为34除以6，约5.666667，泄漏了测试分布。常数通道标记并在本课约定下令除数为1；保存原尺度、回退规则及处理版本，不用测试方差修补。
5. 成功子集内部是100%，全部尝试内是50%；Notebook 3复算。示范训练可以依合同使用成功子集，但必须记录筛选条件，审计总表仍保留失败和接管记录。时间预算耗尽是截断，任务或环境自然结束是终止；应分别保存原因与末步有效性，不能把截断当作成功终止。上述少量日志比例不能替代总体部署成功概率。
