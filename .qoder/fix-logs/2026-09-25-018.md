# Fix Log 018 - 有记忆非线性的 settle 相位没对齐扫描起点，环面积少算 38%

**Date**: 2026-09-25  
**Documents**: `components/wiki/nonlinearity-explorer.tsx`（间隙 backlash 分支的环面积读数）  
**Type**: BUG (Negative case: 组件读数与手算值不符，违反 Fix-014)  
**Summary**: `analyse()` 先跑 3 个周期让有记忆非线性进入周期轨道，但 settle 循环从 `t = 2πi/N` 起、停在 `t = 6π`（`u ≈ 0`，正在**下降支**上）。随后的上升支扫描从 `u = -A` 开始，`prevY` 却带着下降支的残留（间隙时约 `+b`），于是 `y = max(prevY, u - b)` 被钉在 `+b` 直到 `u > 2b - A`，上升支整段错位。环面积算成 0.520000，手算值是 0.84

## Problem

`NonlinearityExplorer` 切到"间隙"（默认 A = 1.00、b = 0.30）时，读数区显示环面积 `∮ y du = 0.520000`。手算：上升支在 `u < -A + 2b = -0.4` 之前平躺在 `y = -A + b = -0.7`，之后 `y = u - b`；下降支对称。

$$\oint y\,du = \int_{-1}^{-0.4}(u+1)du + \int_{-0.4}^{0.4}0.6\,du + \int_{0.4}^{1}(1-u)du = 0.18 + 0.48 + 0.18 = 0.84$$

差了 38%。而同一屏的 `max|y − u| = 0.300005` 是**对的**（恰为 `b`），滞环分支的面积 1.200000 = 4cA 也是对的——所以问题不在 `apply()` 的间隙递推式，只在初值。

## Root Cause

间隙和滞环的输出依赖历史，扫描前必须先"预热"到周期轨道。原代码：

```ts
for (let i = 1; i <= 3 * N_TIME; i++) {
  const t = (2 * Math.PI * i) / N_TIME;   // 停在 t = 6π → u = A·sin(6π) ≈ 0
  prevY = apply(type, A * Math.sin(t), p, prevY, Math.cos(t) > 0 ? 1 : -1);
}
```

末相位 `t = 6π` 落在 `u ≈ 0` 且 `cos t ≈ 0⁻`（下降支），预热结束时 `prevY ≈ +b = +0.3`。上升支扫描却从 `u = -A = -1` 开始：

`apply("backlash", -1, 0.3, +0.3, +1) = max(0.3, -1.3) = 0.3`

输出被钉在 `+0.3`（本应是 `-0.7`），一直到 `u - b > 0.3` 即 `u > 0.6` 才脱开。上升支几乎整段抬高 1.0，`y_rise − y_fall` 大幅失真。

滞环分支之所以没暴露：滞环的 `y = u ± c` 不含 `prevY`，预热残留一个采样点后被冲掉。

## Fix

让 settle 的末相位与上升支扫描的起点重合（`θ = -π/2`，即 `u = -A`）：

```ts
const t = -Math.PI / 2 + (2 * Math.PI * i) / N_TIME;
```

跑满 3 个整周期后停在 `u = -A`，`prevY` 就是周期轨道在该点的值（间隙时 `-A + b`），扫描从这里接续天然正确。

## Rule

**有记忆非线性（滞环、间隙、磁滞、Play/Stop 算子）在扫描前预热时，预热的末相位必须等于扫描的起始相位。** 否则递推初值来自另一条支路，读数会静默错误——不报错、不 NaN，其他读数（如 `max|y−u|`）还可能全对，只有依赖整条回线的量（环面积、能耗、描述函数）失真。

配套纪律：交互组件的每个读数都要有一个能独立复算的镜像脚本（JS 或 Python），拿手算闭式值对一遍；只看"图长得对"抓不到这类错误。
