# Fix Log 015 - 交互组件必须在 lib/content.ts 注册，mdx-components.tsx 不够

**Date**: 2026-09-25  
**Documents**: `lib/content.ts`（影响所有新增交互组件的课程页）  
**Type**: BUG (Negative case: 页面 500 "Expected component X to be defined")  
**Summary**: 本项目有**两份**组件注册表：根目录 `mdx-components.tsx`（Next.js MDX 约定）和 `lib/content.ts` 里 `compileMDX({ components: {...} })` 的显式映射。课程页走的是后者——只改 `mdx-components.tsx` 时，`next-mdx-remote/rsc` 在编译期抛 `Expected component \`PhasePlaneExplorer\` to be defined`，`getLesson` 把它 throw 出去，页面 500

## Problem

重写 `nonlinear/phase-plane` 时新增了 `PhasePlaneExplorer` 与 `TraceDetExplorer`，按以往习惯只在根目录 `mdx-components.tsx` 里加了 import 和导出。TypeScript 全绿、浏览器打开却是 500，报错信息：

```
Error: Expected component `PhasePlaneExplorer` to be defined: you likely forgot to import, pass, or provide it.
It's referenced in your code at `177:1-177:23`
```

`npx tsc --noEmit` 抓不到这个问题：MDX 里的 `<PhasePlaneExplorer />` 对 TS 来说只是字符串，组件映射是运行时注入的。本地 Python harness 也不解析 MDX，同样抓不到。唯一能抓到的是"页面 200"这条硬门槛。

## Root Cause

`lib/content.ts` 的 `compileLessonSource` 调用 `compileMDX` 时**显式传了 `components` 参数**，显式传参会覆盖 next-mdx-remote 从 `mdx-components.tsx` 自动收集的行为。于是根目录那份注册表对课程页完全无效，两份表必须同步维护，而第二份很容易被忘记。

## Fix

在 `lib/content.ts` 顶部补 import、在 `components: {...}` 映射里补 `TraceDetExplorer, PhasePlaneExplorer`。`mdx-components.tsx` 里的那份保留（其它入口可能用到），但**新增组件时两处都要加**。

## Verification

- 补注册前：`GET /nonlinear/phase-plane` → 500，响应体含 `Expected component PhasePlaneExplorer to be defined`；
- 补注册后：`GET /nonlinear/phase-plane` → 200，15 个 H2 == catalog 小节数，控制台无 error，两个 explorer 的 canvas 均渲染，12 个 notebook 的"全部运行"按钮齐全。

## Rule

**新增交互组件 = 三处改动**：`components/wiki/xxx-explorer.tsx`、`mdx-components.tsx`、`lib/content.ts` 的 `components` 映射。交付前必须 `curl` 课程页确认 200——TS 通过不等于 MDX 能编译。
