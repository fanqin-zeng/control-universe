# Wiki修复追踪技能

## 概述

本技能用于在每次wiki内容优化会话中，记录用户提出的反馈和修复内容。每次修复以"正负案例"形式归档——记录修复前的问题（负案例）和修复后的方案（正案例），形成可检索的经验库。

## 文件架构

```
.qoder/
  skills/fix-tracker/
    SKILL.md              # 本文件：技能定义（不变）
  fix-logs/
    INDEX.md              # 按时间倒序的索引（每条≤120字）
    YYYY-MM-DD-NNN.md     # 每次修复的独立记录文件
```

### 分离原则

- **SKILL.md**：定义记录格式和工作流，极少变动
- **INDEX.md**：所有修复条目的索引，便于快速检索
- **YYYY-MM-DD-NNN.md**：每次修复的详细内容，按日期+序号命名

这样做的目的：
1. SKILL定义与数据分离，技能升级不影响历史记录
2. 每次修复独立成文件，避免单文件膨胀
3. INDEX.md只存摘要，快速浏览不需打开每个文件

## 记录格式

### INDEX.md 条目格式

```markdown
| # | 日期 | 文档 | 章节 | 类型 | 摘要 |
```

- 类型：`NEG`(负案例) / `POS`(正案例) / `BOTH`(正负对比)
- 摘要：一句话描述，≤80字

### 单条修复记录格式 (YYYY-MM-DD-NNN.md)

```markdown
---
date: YYYY-MM-DD
doc: content/chapter/lesson.mdx
section: 章节标题
type: NEG | POS | BOTH
tags: [交互组件, 可视化, 内容补充, ...]
---

# 修复摘要：一句话标题

## 问题（负案例）

用户指出的具体问题。原文哪里不好、缺什么、错什么。

## 修复方案（正案例）

做了什么改动、为什么这样做。

## 涉及文件

- `path/to/file1.tsx` — 新建/修改说明
- `path/to/file2.mdx` — 修改说明

## 经验提炼

可复用的经验，供后续类似修复参考。
```

## 工作流

### 记录修复（用户提出反馈并修复后）

1. 确定修复编号：读取 INDEX.md，找到当天最大序号，+1
2. 创建修复记录文件：`.qoder/fix-logs/YYYY-MM-DD-NNN.md`
3. 更新 INDEX.md：在表格顶部插入新条目（最新在前）
4. 如果修复涉及新建组件，在记录中标注组件路径

### 查阅历史

1. 读 INDEX.md 获取所有修复概览
2. 按 tags 或 doc 筛选感兴趣的条目
3. 打开对应的详细记录文件查看完整内容

## 标签体系

常用标签（可自由扩展）：

| 标签 | 含义 |
|------|------|
| `交互组件` | 新增或修改了交互控件 |
| `可视化` | 图表、动画相关 |
| `内容补充` | 补充了缺失内容 |
| `内容修正` | 修正了错误内容 |
| `格式优化` | 排版、结构优化 |
| `公式修正` | 数学公式相关 |
| `代码修正` | 代码示例相关 |
| `体验优化` | 用户体验改善 |
| `翻译/术语` | 术语或翻译问题 |

## 注意事项

- 每次修复只记录**最终方案和决策理由**，不记录讨论过程
- 经验提炼要具体可操作，不要空泛总结
- INDEX.md 超过 100 条时考虑按章节分卷
- 修复记录使用中文撰写
