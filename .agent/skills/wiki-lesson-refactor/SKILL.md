# 重构一节课程

先读并执行 [学期3共同流程](../wiki-discussion/references/semester-03-core.md)，再执行以下重构专用步骤。旧版已签发也不免本轮审校。

## 准备：以原文审计确定范围

确认计划 ID、全部源路径、目标路径、全局 checklist。读全部被沿用正文、旧日志、notebook、组件实际实现和当前页面；记录起点 commit、现有 MDX hash、页内 H2、代码运行状态及已知问题。旧日志是历史证据，不能当本轮实测。

产生改动矩阵并放在日志附录 D：

| 原位置/资产 | 审计证据 | 保留/纠错/重写/迁移/拆分/删除 | 目标位置/去向 | 验证方式 |
|---|---|---|---|---|

逐类检查教学前置、定理条件、推导、正文及答案数值、代码 API、组件默认值、交叉引用和学习负担。此时才确定“本课要重构什么”，不照全局计划预设所有旧课都有同一问题。保留正确且有教学价值的内容，不为展示工作量全文改写。

## Phase 1：以缺陷和目标决定重构

围绕审计结果讨论新教学目标/H2和保留范围。分清内容错误、教学顺序问题、工程失效、仅过时引用，按影响排序。对保留的数值也独立复算；v1.3 状态不等于已核对。

迁移/合并需先列所有旧 URL、锚点、prereq、调用点与资产归属。拆分每个片段都有去向；一个对话只交付一节目标课，剩余片段登记到后续课程，未迁完不能先删源正文。重命名保留重定向，检查不成环、不重定向到空页。大范围结构变更交给计划中的结构任务，不借单课重构偷偷重排全站。

## Phase 2：带证据修正并接受学生反馈

三轮讨论围绕实际旧文和修改稿进行；每条关键结论记录“原断言 → 依据 → 新断言”，删除内容说明重复、错误或移出范围的理由。保留可复用代码时仍使用干净内核实际执行，禁把旧缓存输出当证据。

建立正文/答案/Notebook/React/来源引用的变更传播表，一个模型参数变化要追到所有显示位置。组件比较调用真实实现；既有 API 失效、符号冲突、默认例失配优先处理。修复按既有 fix-tracker 规则登记归因，不把团队扩编当解决方案。

## Phase 3–4：核纠错且核没有遗失

共同门槛之外，逐行关闭附录 D：内容/习题/算例去向齐全；保留的结论已重新验证；迁移前后 URL 和必要锚点可用；组件其他调用课不受回归影响；拆分剩余材料仍可访问。

日志同时呈现纠错证据与未迁材料清单，不能用新文覆盖历史日志或伪造旧结论正确。未迁材料作为后续课计划，不阻止当前边界完整的目标课交付，但必须保留来源且标清状态。共同流程的签发、checklist 和master提交与推送完成后才交付本课。
