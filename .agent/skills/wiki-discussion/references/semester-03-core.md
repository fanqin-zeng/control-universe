# 学期3讨论流程共同约束

供 `wiki-lesson-new` 与 `wiki-lesson-refactor` 共同引用。两技能的准备工作不同，Phase 1–4 和质量标准相同；不得通过换技能绕过验收。

## 入口与角色

1. 读根目录 AGENTS.md、学期3 plan、全局 checklist，确认本次唯一课程 ID、目标路径及下一项工作。正式课程元数据仍以 content/catalog.ts 为准，计划表只是待实施目标。
2. 读 [既有讨论技能](../SKILL.md) 的《角色上场规则》《发言纪律》《讨论日志固定结构》《数值三方对账》《前端交付硬门槛》《定量对比红队审查》，以及 [personas.md](../personas.md) 中本课出席角色。保留 22 人池、14 类轮值、课型矩阵和否决权，不另造团队。
3. 7–10 人按课型上场；郑核、苏绘、孙助、柯验必到，math 加岳自。新章按课型匹配现有领域专家与主责教授，在 Phase 1 说明依据。秦构执行前端验收；不以“未列常设”免除其工作。
4. 角色是结构化审查视角，不冒充真实外部专家或独立 Agent。发言需包含依据、问题或可执行决定；禁止轮流赞同凑数。缺席显式写 `[沉默-角色：原因]`，分阶段解释，无须把未出席的全池成员逐人复制四遍。
5. 一个对话只交付一节目标课。前置不足先在 checklist 登记阻塞，不悄悄顺带生产另一课。未完保存检查点，不能预填签发和验收。开始后发现路径/范围需要调整，先更新计划映射和 checklist，再继续；结构变更需保留原始来源覆盖。

## Phase 1 内容规划

先把讨论和决定写入 `docs/discuss-log/semester-03/<章序>-<章slug>/<课序>-<课slug>.md`。序号取当时 catalog，课程 ID 写在头部，不随显示顺序变化。

- 主责给出 3–5 个可验证学习目标、读者起点、非目标、H2 草案、真正用到的先修。math 从高中数学起步，每个新概念有直觉、定义、小例子、控制用途；不把尚未交付课程当已知知识。
- 苏绘逐小节判定纯图文 / notebook 静态计算 / React 调参；没有调参价值不强制造 Explorer。孙助提供与目标对应的基础题、推导或解释题、应用题与答案核验方式。
- 何仿提交数值实验合同：对象、单位、初值、参数、步长、时域、统计窗口、指标、随机种子、运行预算。柯验先约定断言清单和逐量容差；未实跑的数字标待测。
- 有比较时何疑预审基线、整定预算、≥3 工况、落败/持平工况；学习类区分训练/验证/测试、环境步数与墙钟时间，禁止泄漏或只挑好种子。
- 新兴技术记录作者论文/官方代码版本、检索日期、许可证与可复现范围；分清作者实测、课程复现和教学简化。大模型课采用可运行小实验或明确标注的预计算演示，不能声称本机训练了完整模型。

## Phase 2 内容生成（必须三轮）

1. 概念讲解：由问题到模型、假设、推导、实现和边界，写正文及配套实验。
2. 学生反馈：按真实草稿指出卡点或反例；math 由岳自复述关键概念，不能把教师自己复述当学生验收。
3. 调整完善：逐项记录反馈 → 修改位置 → 复核结果，未解决项带责任视角和下一步。

记录应随实际工作逐阶段形成，禁止全部写完后伪造一场“早已完成的讨论”。内嵌 notebook 必须用页面上的原始 setup/cell 实跑；禁止 ipywidgets。同页 kernel ID 全局唯一、JSX 属性无逗号、多行公式的 `$$` 独占开闭行、cell 不以 `%#` 开头。组件只在 lib/wiki-components.ts 注册并在 MDX 显式引用。

## Phase 3 内容审校

按原日志固定的六组：教授、工程、验证、体验与脉络、教学支持、学生。缺席有原因，工作不能因人缺席而漏检。

- 教授核假设、定理条件、符号、可实现性与适用域；工程核饱和、噪声、延迟、采样和资源预算。
- 柯验独立于何仿复算正文及答案全部数值断言；A.1 保留原六列 `# / 正文断言 / notebook 输出 / 组件默认值读数 / 一致? / 备注`，备注写 cell、参数、单位、窗口、容差。存在的路线必须实测；不适用路线写原因，不能用不适用掩盖未执行。无数值断言用原规则的明确空清单行。
- JS/TS 组件需实际调用其计算实现与独立 Python/解析结果对照，不能再抄一份相同算法自证；默认值复现正文算例，至少检查一个边界参数。离散末样值不冒充稳态极限，采样峰值不冒充连续时间精确峰值，抽稀后使用真实时间轴。
- 秦构逐项执行原技能的九项硬门槛，不重编号、不删项；B 附实际命令、退出码与关键输出。S6 内核执行不得 SKIPPED 后签发。ECharts animation:false、显式坐标上下界、inline style 兜底；检查参数变化、默认恢复、布局及浏览器错误。
- 何疑逐条审定量、半定量和图形比较，C 附原六列放行表。独立整定基线、≥3 工况含失败/持平、正文写边界和代价；随机方法报告多种子及分布。无比较恰好一行 `[沉默-何疑：本课无对比结论]`。限定观察按原技能处理，不能换措辞隐藏强结论。
- 孙助核习题答案与学习目标，陆阅核可读性及四份档案（缺席由郑核代核）。否决回 Phase 2，修后重测受影响项，不保留过期读数。

## Phase 4 定稿与合入

日志采用原固定骨架：头部/出席、Phase 1、Phase 2 三轮、Phase 3 六组、Phase 4、附录 A.1 对账+A.2 实测总表、B 九项门槛、C 红队放行；准备审计或设计合同可加附录 D。原始输出留在日志附录或链接的版本化证据文件，不能只指向本机临时 logs。

1. 逐项核对学术修改、柯验全部对账、何疑放行、秦构九项、习题答案、档案；未决项不能影响本课正确性。郑核有依据才签发。
2. 执行 `npm run check`、`npm run verify -- <chapter>/<lesson>`、`node scripts/nb-cells.mjs verify <chapter>/<lesson> --require-kernel`、适用术语检查、`npm run build`。I04起数值交付使用严格内核选项，setup与cell错误都必须失败；无内核的静态检查不算数值验收。复验环境、隔离、独立数值和页面链路可运行 `node scripts/verify-reproducibility.mjs --out <证据文件>`，该抽样不替代本课完整三方对账。查看 verify 的参数文档选择单课检查，不能将全站旧课失败误记为本课通过。build 除 exit=0 还需无 MDX 编译失败。I01查明吞错发生在课程路由的catch→notFound，而非已重新抛错的lib/content.ts；修复后仅目录外地址404，目录内读取/编译错误必须上抛并使构建失败。变更错误处理时必须运行 `node --test scripts/lesson-route.test.mjs`，不得恢复宽泛catch。基础设施阻塞记录全局 checklist，未解除不得虚签。
3. 正文、组件、注册、catalog status=v1.3、旧 tracker（如适用）、自动 OUTLINE、讨论日志、学期3 checklist 和适用计划修改同提交。学期3完成只认本期日志证据，不继承旧 v1.3 标签。
4. `npm run check -- --fix-outline`、`--fix-tracker-stats` 按变更使用；在工作包分支验收后 `git merge --no-ff` 合 master。记录真实提交/合并 hash 和输出后才勾“合并”。多课包每课即合，未完分支继续留存；不碰用户未提交文件。
5. 报告本课成果、验收和下一课；本对话到此停止，不自动生产下一课。学期末复盘沿用 fix-tracker，记录问题是规范缺口还是规范未执行。
