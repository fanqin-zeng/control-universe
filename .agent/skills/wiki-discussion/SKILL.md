# Wiki讨论式内容生成工作流

## 概述

> **学期3入口（2026-10-17）**：新写课程使用 [wiki-lesson-new](../wiki-lesson-new/SKILL.md)，已有正文重构使用 [wiki-lesson-refactor](../wiki-lesson-refactor/SKILL.md)，并执行 [共同流程](references/semester-03-core.md)。本文件保留为既有角色矩阵、讨论纪律和质量门槛的共同权威，历史日志不回写；学期3新增执行约束由共同流程统一承载。

本技能定义了一套多角色讨论框架，用于生成和优化控制理论wiki课程内容。内容通过八个具名层面（外加轮值领域专家）的角色结构化讨论产出，确保内容兼具学术深度、工程实用性、教学质量、数值可信度与可读性。

## 学期3语言职责更新（2026-10-18用户裁决）

在原课型阵容上追加文简（实际润色）与沈读（终稿顺读审核），单课9–12人。当前24人及否决权以personas团队全貌为准；历史B3数据保留来源说明；下方当前必到名单与总人数已按新增角色同步。两角色按 [表达与顺读规则](references/language-review.md) 接入四阶段，沈读终稿后更新学期记忆。历史日志不回写。

### 可视化（1人）— 图文呈现

| 角色 | 姓名 | 专长领域 | 核心职责 |
|------|------|----------|----------|
| 技术可视化设计师 | **苏绘** | 技术插图、信息图表、可视化策略 | 决定何时用AI生成概念图、何时用动态图表组件 |

**苏绘的可视化策略（v1.3）**：

本项目的可视化分为两种场景，使用不同的技术方案：

| 场景 | 判断标准 | 技术方案 | 说明 |
|------|----------|----------|------|
| **代码演示** | 用代码将抽象概念具体化，展示计算过程、算法流程、数据验证，输出文本或图表 | `<JupyterNotebook>` 组件，静态输出即可（文本/表格/图表） | 重点是"让代码说话"，读者不需要调参 |
| **交互探索** | 展示参数变化对系统特性的影响，需要读者自行探索 | React 交互组件（ECharts + useECharts hook） | 重点是"拖动看变化"，必须有可调控件 |

**交互组件设计规范**：
- 使用 ECharts 渲染图表，配合 `useECharts` hook
- 固定坐标轴范围（避免拖动时坐标轴缩放导致视觉混乱）
- 禁用动画（`animation: false`），保证拖动时即时响应
- 控件类型不限于滑块，可根据需要选择：滑块、按钮组、下拉菜单、开关等
- 组件放在 `components/wiki/` 目录，命名如 `xxx-explorer.tsx`

**决策流程**：
```
这段内容需要可视化吗？
├── 否 → 纯文字/公式
└── 是 → 读者需要调参探索吗？
    ├── 否 → <JupyterNotebook> 静态输出（文本/表格/图表）
    └── 是 → React 交互组件（<XxxExplorer>）
```

> **v1.3 原则**：ipywidgets 在本项目的轻量级 Jupyter 服务器上不可用（无法渲染 widget）。所有交互需求必须用 React 组件实现。

### 1. 核心常设 6 人（每课必到）

| 角色 | 为什么是这 6 人 | 实质发言的阶段 |

### 6. 自检规则（每次改本节、增删角色或改课型矩阵后必须重跑）

1. **当前上场总人数为原课型阵容加文简/沈读，通常9–12人。** 两名语言角色不得为了压回旧7–10人而删去，技术/学生/轮值职责仍按矩阵覆盖。历史B3人数为原22人池基准；如专项再增加角色，写明具体职责，不凑数发言。
2. **去重与计数口径**：同一人同时出现在核心名单与追加名单里只算 1 次（例如 `theory` 课的主责教授若正是林矩，总人数为 8 而非 9）；轮值专家按实际匹配的类数计（1 或 2），故 `case` / `frontier` 是一个区间。
3. **不得为了凑人数把角色加进追加名单**——每个追加角色都要能说清「他在这门课上要拦下哪一类返工」，说不清就不加（§3.1 第 1 条：每个角色对应一类可观测的返工）。
4. **新增课型时**（即扩 `content/catalog.ts:14` 的 `type` 联合类型）必须同时给出：追加名单、catalog 现存的典型课程、人数自检结果，并同步更新本节与 `personas.md` 的 `## 团队全貌`。

### 1. 发言配额

| 阶段 | 每角色上限 | 常态 |
|------|-----------|------|
| **Phase 2** | **每轮最多 3 条**（M1 原文），超出必须合并为一条 | **1 条**，多件事用 ①②③ 在一条内分点 |
| Phase 1 / 3 / 4 | **每阶段最多 3 条**（B4 自行裁定：M1 只写了 Phase 2，但既有实践的 Phase 1/3/4 同样是一人一条） | 1 条 |

- **为什么常态是 1 条而不是 3 条**：既有实践更好。`docs/discuss-log/semester-01/07-nonlinear/02-phase-plane.md` 的 Phase 1 里，`[林矩]` 用一条发言装下 5 个数学骨架分点（`:18`）、`[卫韧]` 用一条装下 3 个「线性化会说谎」的现场（`:20`）；11 篇日志无一处出现同一角色在同一轮连发多条。**取舍理由**：拆成多条会让同一角色的论点被别人的发言打断，读者无法一次看全他的完整判断——而讨论日志的主要用途是事后追溯「这个结论当时是谁、凭什么下的」。
- **3 条是硬上限，不是目标值**：撞到上限说明该角色没提炼，应合并而不是继续发。
- Phase 1 的三条一句话结论（苏绘 / 孙助 / 柯验，见《角色上场规则》§1）**各算 1 条**，不因「只是一句话」而免计。

### 2. 沉默机制

**按《角色上场规则》§5 应到、却无实质贡献的角色 → 必须显式标记，并写进讨论日志第 2 节「出席与沉默表」。**

标记格式 `[沉默-<角色>：<原因>]`。M1 给的三个示例：

- `[沉默-范安：本课无安全相关内容]`
- `[沉默-许史：本课无历史脉络可补充]`
- `[沉默-吴规：本课不涉及上游规划接口]`

第四个既有示例（B2 已写在《讨论标记约定》里，B4 保留）：`[沉默-岳自：本课非 math 章]`——**只在非 `math` 章成立**，`math` 章不得沉默（见本节末的两个例外）。

**原因必须可核查**：说清「这门课为什么不需要该角色的视角」，不得写「无」「没话说」「同上」。判定方法——把原因读给郑核听，他能否据此判断该角色确实无可补充。

- ✗ `[沉默-何疑：本课不涉及]`（不涉及什么？）
- ✓ `[沉默-何疑：本课无对比结论，全部数字是单一方法的实测读数]`
- ✓ `[沉默-陆阅：本课非 math/history 课型，档案核查由郑核代执行]`（《角色上场规则》§5 的既定写法）

**轮值领域专家**的沉默写法：`[沉默-轮值：本课为纯数学推导，无应用场景]`。`case`（11 课）与 `frontier`（2 课）课型轮值必到，**不得沉默**。

**两个不能用沉默代替到场的例外**（B2 / B3 已立，此处重申）：

1. `math` 章的**岳自**——缺席则郑核不得签发该章课程；
2. 持九项前端硬门槛的**秦构**——门槛的实际输出必须粘贴进附录 B，缺席则无档案可核。

### 3. 禁止的发言类型

**无信息发言一律删除或改写。** M1 点名三类：「我同意 XX 的观点」「这个很重要」「说得对」。

### 3. 与既有实践的取舍（冲突时以更好的部分为准，理由如下）

1. **共识与待定不单列顶层章节。** 既有 11/11 篇把 `[共识]` 写在 Phase 1 末尾，那是它产生的位置；抽出来单列会让 Phase 1 失去收尾、读者要在两处来回跳。**新增的硬要求是 `[待定]` 必须显式出现**（既有 0/11）——「没有待定」与「忘了写待定」必须可区分，无待定也要写「无」。
2. **附录 A 拆成 A.1 + A.2。** Prompt 要 A 是柯验的三方对账表，而既有 5 篇设了「附录 A」，装的是**实测数据总表**（**B5 更正**：本条原写「表头两种」并把 `03-describing-function.md` 归到 3 列表头下；逐篇实测有 **5 种**形态——`| 来源 | 量 | 实测值 |` 只 **2 篇**：`07-nonlinear/01-nonlinear-characteristics.md:134`、`02-phase-plane.md:128`；`03-describing-function.md:138` 用的是 `| 编号 | 实验 | 关键结果 |`；另有 `| 实验 | 预测 | 实测 |` **3 篇**、`| 实验 | 场景 | IOL | Jacobian | 结论 |` 1 篇、`| 项 | 值 |` 1 篇（`08-intelligent/01-fuzzy-control-basics.md:122`）。完整清单见《数值三方对账》§7）。两者目的不同且都不可丢：A.1 回答「正文的每个断言是否被两路测量支持」，A.2 回答「这门课一共测了什么、每个数字从哪个 cell 来」。**A.2 采用 3 列表头 `| 来源 | 量 | 实测值 |`**（裁决不变，但理由换成不依赖篇数的说法：多出的「来源」列正是产出路径，没有它「可溯源」就无法核查；`| 编号 | 实验 | 关键结果 |` 用「编号 + 实验」承载同一信息，按《数值三方对账》§7 **可接受为等价形态**，存量不回改）。A.2 承担着郑核「无知识幻觉」核查的实际职能（同文件 `:112`：「附录 A 列出正文与习题引用的每一个数字及其来源 cell」），且覆盖 A.1 覆盖不到的部分（未在正文断言的测量，如 NB2 的 2000 次随机矩阵互核）。**「全部实测数据的唯一留存副本」这句注明挂在附录 A 整体上**（A.1 + A.2），比只挂 A.1 准确。
3. **附录 B / C / D 的字母重排。** Prompt 的 B = 秦构硬门槛、C = 何疑放行；既有的 B = 修正对照、C = 环境与浏览器验证。**按 Prompt 的语义固定字母**——因为 B5 / B6 / B7 会把 M2 / M3 / M4 的细则分别挂到这三个字母上，字母错位会让后续三个阶段全部指错地方。然后：既有「附录 C：环境与工具链问题 / 浏览器端到端验证」**并入新附录 B**（它本来就是硬门槛的实际输出——`01-fuzzy-control-basics.md:171`–`:180` 的九条与 M3 九项几乎一一对应）；既有「附录 B：旧稿错误 → 本次修正对照」**顺延为附录 D，一字不删**（它是 B5「叙述服从测量」的正例来源，也是 M5 fix-log 归因的原始素材）。
4. **签发结论留在 Phase 4，不挪到附录之后。** 既有 10/11 篇的 `[郑核-签发]` 都在 Phase 4 内（唯一缺的就是 `03-neural-network-control.md`）。签发是 Phase 4 的动作，挪走会让 Phase 4 变空壳；且附录是证据、签发是判断，「先给结论、证据附后」更符合日志的读法。
5. **元数据 6 → 7 行，并固定标题、冒号、发言标记与 `参与者：` 行的形态。** 新增「课型」的理由：B3 起上场名单由课型决定，日志必须能被反查「这门课该派谁、实际派了谁」；catalog 缺 `type` 时（Q22 的 67 门）要写成 `<type>（catalog 缺 type，按《角色上场规则》§4 兜底表判定）`。其余一律取多数派：标题 `# 课堂讨论日志：<标题>（<chap> / <lesson>）`（9/11）、H2 半角冒号 `## Phase 1: `（10/11，唯一的全角在 `08-intelligent/02-fuzzy-controller-design.md:9`）、发言标记 `[角色] `不加粗（10/11；`03-neural-network-control.md` 用 `**[角色]**：`，会让 `[沉默-…]` 与 `[共识]` 匹配不到同一套正则）。**`参与者：` 行只在 Phase 1 写一次**（既有 9/11 的形态，不加「（本阶段发言者）」这类修饰）——各阶段的到场情况改由「出席与沉默表」的**实质发言的阶段**列承载，比在每个 Phase 重复一行 `参与者：` 更可核查（重复行无法表达「到了但没发言」）。「日期」的口径 = **交付日期**。
6. **Phase 3 分组 4 → 6。** 新增「验证团队（独立把关）」与「体验与脉络（读者、历史与安全）」，与本文件 Phase 3 正文的六组条目**同名同序**。既有 11 篇只有 4 组，因为这两个层是 B1 才设立的——属**新增而非冲突**。
7. **Phase 4 采纳既有实践里更好的两处，并新增两处。**
   - **采纳①（既有更好的部分）**：`[郑核]` 汇总行按 `04-lyapunov-stability.md:118` 起的 9/11 篇形态写——**按角色列出各自条数 + 标 P0/P1 优先级 + 无 P0 时明写「无 P0 阻断项」**。这比「汇总 N 条」信息量大：P0/P1 让「有没有被阻断过」可事后追溯。
   - **采纳②**：`[郑核-复核签发]` 保留为合法标记（既有实践见 `05-feedback-linearization.md:192`，签发后发现 3 处叙述被实测推翻 + 1 处全站级组件 bug，修完重签）。口径：`[郑核-签发]` 仍恰好 **1** 次，复核签发**不限次数但每次必须写明重签理由**。
   - **新增①**：`[待定]` 必须显式出现（既有 0/11），无待定写「无」——见取舍 ①。
   - **新增②**：`交付清单：` 行（既有只有 3/11 写了「交付物：」或「交付清单：」，8 篇没有）。它是陆阅核查交付完整性的落点，故升为必填；名称取「交付清单」（fuzzy 01 的形态），因为清单比「物」更明确地要求逐项列出。
8. **Phase 1 的发言顺序：三条一句话结论放在 `[共识]` 之前，`[苏绘]` 的详细展开保留在 `[共识]` 之后（可选）。** 实测既有 9 篇（凡写了 `[共识]` 与 `[苏绘]` 的）都是「`[共识]` 在前、`[苏绘]` 紧随其后隔一行」；而 B3 已把苏绘/孙助/柯验的三条一句话结论定为共识的**输入**（《讨论流程》Phase 1 第 11 条：「第 8–10 的三条结论必须写进共识条目」）。输入必须在结论之前，否则「共识里包含苏绘的结论」在日志里读不出因果。**取舍：两者都保留**——一句话结论前置（B3 的要求），详细展开后置（既有 9/9 的形态，信息量更大：`02-phase-plane.md:36` 的苏绘展开写出了两个组件的面板构成与硬约束，是 `[共识]` 那一行装不下的）。这不违反《发言纪律》§1（Phase 1 每角色最多 3 条，苏绘 2 条）。**另需说明**：`[孙助]` 与 `[柯验]` 在既有 11 篇的 Phase 1 里出现 **0 次**（`[孙助]` 的首次发言都在 Phase 2 第三轮、`[柯验]` 是 B1 才设立的角色），所以他们的 Phase 1 一句话结论属**新增要求，不是与既有实践冲突**。

### 4. 机器可校验的口径（陆阅核、郑核复核）

1. 标题行匹配 `^# 课堂讨论日志：.+（.+ / .+）$`，恰好 1 行。
2. 元数据 7 个字段齐全且顺序固定：学期 / 章节 / 课程 / **课型** / 日期 / 轮值领域专家 / 本次性质。
3. `^## 出席与沉默表$` 恰好 1 行；**核心常设6人（郑核、苏绘、孙助、柯验、文简、沈读）+ 该课型追加名单的每个角色都必须在表内**；`math` 章另含岳自，六位核心及math的岳自状态必须是「出席」。
4. `^## Phase [1-4]: ` （半角冒号）恰好 4 行。
5. `^### 第[一二三]轮 ` 恰好 3 行。
6. Phase 3 的 6 个 `^### ` 分组名与 §1 骨架逐字一致。
7. `[共识]` / `[待定]` / `[郑核-签发]` 各恰好 1 次；`[郑核-复核签发]` 0 次或多次（每次必须带重签理由）；每个缺席角色恰好 1 条 `[沉默-<角色>：<非空原因>]`。`[共识]` 之后、`## Phase 2` 之前的发言只允许是 `[苏绘]` 的可视化展开（取舍 ⑧）。
8. `^## 附录 [ABCD]：` 恰好 4 行；附录 A 含 `^### A\.1 ` 与 `^### A\.2 ` 两行。

### 4. 「一致」的判定标准

只有把「一致」定义清楚，否决权才既不会被打回一切、也不会被用来放过一切。

- **取值只允许三个**：`✅` 一致 / `❌` 不一致 / `—` 该路不存在（备注里写明为什么不存在，例如「本课无交互组件」「该量组件不显示」）。**不许留空，不许写「基本一致」「大致吻合」「量级相符」**。
- **✅ 的口径 = 同一个量的两路（或三路）独立测量，差异落在双方都已声明的精度之内**。三种情形判 ✅：
  1. **同源不同实现**：notebook 的 Python 与组件的 JS 各算一遍，差在积分步长 / 网格密度可解释的量级（示例第 2 行：6.380676 vs 6.380664，相对 1.9e-6）。
  2. **方法固有偏差且正文已写明**：描述函数法只取基波，与时域全仿真差 +4.87% 是**方法本身的性质**，不是实现错误——前提是正文把这个偏差讲清楚了（示例第 1 行）。**若正文没写，先判 ❌**，按 §6 改叙述后再转 ✅。
  3. **网格 / 二分精度限制**：组件按 0.05 rad/s 网格找穿越点、再用 60 步二分反解 A，读数 0.4241 vs 手算 0.424413（0.07%）——把网格步长写进备注即可。
- **❌ 的口径**：① 任一路与另一路的差**超出**双方声明的精度；② 某路交不出产出路径（何仿给不出 cell）；③ 正文的数字在 notebook 与组件里**都找不到对应测量**——即「写出来的数」而不是「算出来的数」；④ 组件的**默认参数**下复现不出正文的手算例（fix-014 的原形态）；⑤ 统计窗口或判据未声明，导致两路数字不可比。
- **容差不是全局常数**：由柯验按量纲与算法**逐行写进备注**（例：环面积 1e-6、周期 1e-5 s、发散时刻 ±0.05 s、傅里叶基波 1%）。**写不出容差的行不允许判 ✅**——写不出就意味着没人知道它该多准。
- **符号、单位、有效位数、正负号、实虚部约定先对齐，再比数**：`nonlinear/describing-function` 重写事故的根因之一就是 N = (a₁+jb₁)/A 的实虚部写反、−1/N 轨迹方向写反；约定不一致时两路的数「碰巧相等」也没有意义。

### 5. 不一致的处置：一票否决

- **任一行 ❌ → 柯验行使否决权，打回 Phase 2，禁止进入 Phase 4。** 不接受「先签发、下个版本再改」，也不接受「差得不大就放过」——fix-016 的 20 倍与 fix-018 的 38% 在页面上都「看起来对」。
- **打回时必须指明是哪一路错**：正文错（改叙述）／notebook 错（改实验）／组件错（改实现）。三路都对但口径不同 → 归到 §4 的容差与窗口声明问题，**改备注而不是改数**。
- **修完必须整表重测**，不许只补出问题的那一行。fix-016 的直接教训：第一次修只把 `def.T` 换成 `Tlong`，消掉了一个**独立的 2 倍**误差，**20 倍那个还在**；只重测被改的一行就永远发现不了第二个因子。判据是**根因**，不是「数看起来近了」。
- **每次改叙述都要在附录 D 留一行**（原说法 / 实测 / 处理）。这既是 M2 的可追溯性，也是 M5 fix-log 归因的原始素材。

### 6. 「叙述服从测量」的操作细则

**测量与预期不符时，只允许两条路：① 改叙述，或 ② 改实验设计（含重新整定基线）。不允许改数据。**

**① 改叙述**——把正文改成测量说的那样，并在附录 D 记下原说法。

- **正例 A（一开始就按实测写，所以从未进过修正清单）**：`adaptive-control-basics` 的 γ。正文「直觉待拆」表里那一行写的是——γ 从 0.5 加到 10 时确实变快（拟合速率 0.00675 → 0.04060 per s），但 γ=200 在 t=400 s 时残差 5.996e-4、γ=1000 卡在 1.715e-2，都比 γ=10 的 4.491e-8 差好几个数量级（`content/nonlinear/adaptive-control-basics.mdx:29`）；小结据此给出「自适应增益 γ 存在一个**上界**，上界由未建模动态的带宽决定」（`:2039`）；再用 Rohrs 型实验坐实：γ ≤ 3 有界、γ ≥ 4 发散，发散时间随 γ 单调缩短（5.20 s → 0.76 s），dt 减半结果完全一致、不是数值假象（`:2666`）。**这段没有一处是「理论上应该」**，所以它没被测量推翻过。

**② 改实验设计**——当实验本身不足以支撑（或不足以推翻）叙述时，改设计而不是改数。包括：重新整定基线（与何疑的红队放行三条件衔接——基线没整定过就「赢了」，赢的结论本身无效；接缝见《定量对比红队审查》§7）、改 dt 规则、改统计窗口、加对照工况、换参考信号让 PE 条件成立。

## 定量对比红队审查（B7 起）

> **来源**：`semester-02-plan.md` §3.7 M4。**执行者**：何疑（红队审稿人；不是核心常设 6 人，但每课必到——本课无对比结论时写 `[沉默-何疑：本课无对比结论]`，不得缺席）。**否决权**：有（论证公平性）。**与柯验的分工**：柯验查「这个数是怎么算出来的」，何疑问「那个基线整定过没有」，两人对同一句断言各查一半，都过才算过（见《数值三方对账》§7）。

### 1. 适用范围：什么算「对比断言」

凡形如「A 优于 B」「A 比 B 快 X%」「A 更鲁棒」「A 的 rms 只有 B 的 1/7」的**定量或半定量**断言，都在何疑的放行范围内。三类容易漏掉的：

1. **半定量措辞也算**——「远优于」「几乎持平」「显著更稳」「差一个数量级」「结构性上限」这类没有精确数字但表达了强弱次序的词，同样是断言（触发词表见本节末）。
2. **对比图本身也是断言**——交互组件里两条曲线画在同一张图上、notebook 输出的对比柱状图 / 表格，只要读者能从图里读出「谁好谁坏」，这张图就和一句「A 优于 B」等价，必须过三条件。图不能因为「没写文字结论」就豁免。
3. **跨课传播的断言也算**——本课若引用了上一课的对比结论（如「上一课已证明模糊 PD 控不住这台摆」），何疑要追到源头那一课核它当初是否放行过；源头没有放行记录 → 本课不得直接继承该结论（Q23 就是这个缺口，见 §8）。

触发词表（出现即触发审查）：优于 / 远优于 / 超过 / 快 X% / 慢 X% / 更鲁棒 / 更稳 / 更省 / 显著 / 几乎持平 / 差一个（几个）数量级 / 结构性上限 / 硬上限 / 完胜 / 碾压 / 只有……的 1/N / 是……的 N 倍。

### 2. 放行三条件（逐字来自 §3.7 M4，任一不满足即否决）

对每一条对比断言，何疑逐条核以下三条件，三条全过才放行；放行与否及依据写进附录 C 的放行表（骨架见《讨论日志固定结构》§1）。

**条件 a（基线整定过）**：被比较的基线 B 必须在**同一被控对象、同一评价指标**下**独立整定过**，并在附录 C 记录**整定方法**（手算 / LQR / 试凑 / Ziegler-Nichols…）与**参数扫描范围**（扫了哪个参数、从多少到多少、几个点）。

- 判据：附录 C 该行「基线整定与扫描范围」列非空、写得出方法与范围。只写「默认参数」「随手取的增益」「文献值」而无扫描 → 不满足。
- **为什么**：基线没整定过就「赢了」，赢的结论无效——这正是 ABS 事故的病根（见 §4）。

**条件 b（≥3 组 + 全量入附录）**：至少在 **3 组参数或 3 个工况**下对比，且**全部结果**（含 A 输给 B 的场景）写入讨论日志附录 C，不许只挑 A 赢的那几组进正文。

- 判据：附录 C 该行「组数与落败场景」列写明组数 ≥ 3，并至少举出一个 A 落败 / 持平的具体场景（参数或工况 + 数字）。
- **为什么**：单点对比无法区分「A 真的更好」与「这一组恰好如此」；只报赢的点是幸存者偏差。

**条件 c（正文诚实列边界）**：正文必须诚实列出 **A 不如 B 的场景**与 **A 的适用边界 / 代价**，不能只写 A 的好。

- 判据：正文对应段落能找到明确的「A 在……下不如 B」「A 的代价是……」「适用边界是……」一类表述，且与附录 C 的落败场景一致。
- **为什么**：没有边界的「A 优于 B」是过度推广；读者需要知道什么时候该用 B。

### 3. 三种合法放行 vs 五类不放行

**合法放行（写进附录 C 放行表的「放行」行）**：

1. 三条件全过，正文断言与附录 C 的落败场景、边界一致 → 放行。
2. 断言被降级为「在本组参数下观察到 A 的 rms 更低」这类**限定语境的观察**（不再声称普适优越）→ 放行（它已不再是需要三条件的强断言）。
3. 本课确无任何对比断言 → 附录 C 写**恰好一行** `[沉默-何疑：本课无对比结论]`（空表与「忘了做」必须可区分）。

**五类不放行（何疑行使否决，退回 Phase 2）**：

1. 基线没整定过（缺条件 a）——典型：基线用默认 / 随手参数，己方方法却精调过。
2. 只比了 1~2 组，或附录 C 里找不到 A 落败的场景（缺条件 b）。
3. 正文只写 A 的好、无边界无代价（缺条件 c）。
4. 指标挑选偏差——只报对 A 有利的指标（如只报超调不报稳态误差），换指标结论就翻。
5. 断言来自跨课继承而源头无放行记录（见 §1 第 3 类）。

### 4. 反面案例：ABS 稻草人基线（`intelligent/fuzzy-control-basics`）

- **事故**：本节最初把 ABS 对比基线的门限逻辑写成「每步继电器」，导致在湿卵石路面上该基线**比无 ABS 还差**——这是个稻草人基线，使整节「模糊 ABS 更优」的对比结论失去说服力。
- **数字**：修正前基线制动距离 **47.243 m** vs 模糊 **44.352 m**（`docs/discuss-log/semester-01/08-intelligent/01-fuzzy-control-basics.md`），看似模糊赢，实则赢在一个没整定过的基线上；另有 `sd < -2.0` 的符号错误。
- **病根**：基线违反了条件 a——没有在同一被控对象、同一指标下独立整定过。何疑若在场应当场否决。
- **修法**：把门限逻辑改成速率型三段逻辑，并在三种路面上扫参（滑移率带 $s_{hi}=0.13$ / $s_{lo}=0.08$、减压 12000 / 增压 3000 N·m/s，共 96 组）后才算公平；修正后基线在全部路面都不劣于无 ABS，对比才成立。
- **教训（一句话）**：**对比基线必须整定过**——赢一个稻草人不叫赢。

### 5. 正面案例的标准写法：`nonlinear/adaptive-control-basics` 的四方对比

`content/nonlinear/adaptive-control-basics.mdx:2584`–`:2604` 是最接近满足三条件的范本——**同一个对象、同一个参考、同一段爬升剖面**下比固定增益 / 增益调度（表精确）/ 增益调度（表偏差 30%）/ MRAC 四方（rms |e|，顶点后）：

| 方案 | rms \|e\|（顶点后） |
| --- | --- |
| 固定增益（海平面整定） | 9.34e-1 |
| 增益调度（表精确） | 2.17e-16 |
| 增益调度（表偏差 30%） | 1.25e-1 |
| MRAC（Γ=200） | 3.46e-4 |

- **满足条件 b**：四组方案同台，全部结果（含「MRAC 比精确调度差约 12 个数量级」这一**己方落败**场景）都写进正文与讨论日志附录。
- **满足条件 c**：正文给了明确的选择建议与边界（`:2604`）——调度变量可测且数据表可信 → 增益调度；数据表不可信或变化超预期 → 自适应；两者叠加常见。

### 6. 其他常见论证缺陷（除三条件外，何疑必查）

三条件之外，何疑还要查以下 7 类论证缺陷（与 personas.md 何疑条目的可勾选清单一一对应）：

1. **指标挑选偏差**：只报对己方有利的指标（只报超调不报稳态误差、只报 rms 不报 TV(u)）。换指标结论就翻的，不放行。（正例：`neural-network-control` 同时报了 rms 2.66° 与 TV(u) 13.4，NN 与 PID 的 2.67° / 16.0 各有胜负，没有只挑一个指标。）
2. **只报均值不报方差**：随机 / 学习类方法只给一个均值，不给方差或多次运行分布 → 无法判断差异是否真实。
3. **幸存者偏差**：只展示调好的那次（如固定 `np.random.seed(42)` 的好种子），不报失败的种子 / 初始化。
4. **样本量不足**：n 太小（单次运行、单个初值）就下「A 更鲁棒」的结论。
5. **显著性未交代**：给了「超越 PID 5.3%」这类数字，却没说这 5.3% 是否落在噪声 / 容差之外（Q21 的缺口）。
6. **失效场景敷衍带过**：「局限性讨论」一节名义上在讨论局限，实则一笔带过、没有具体的失效工况与数字。何疑要核这一节是否**真的**在讨论局限。
7. **基线是否有代表性**（B2 登记的缺口，B7 补为第 7 条）：即使基线整定过，还要问它是不是一个**有代表性**的基线——是不是挑了个弱对手（strawman）。ABS 事故里问题不只是「没整定」，更是整定成了一个不代表真实 ABS 的稻草人。

### 7. 不放行的处置（与柯验「叙述服从测量」同族，但对象是结论不是数字）

何疑判不放行后，只许以下三种处置之一，**禁止改数据 / 改测量来让结论成立**：

1. **删结论**：把该对比断言从正文删掉（若图本身就是断言，连图一起删）。
2. **降级为限定观察**：改成「在本组参数下观察到 A 的 rms 更低」这类不声称普适优越的表述（§3 合法放行第 2 种）。
3. **改实验设计重测**：回到 Phase 2，把基线整定过、补足 ≥3 组、补上落败场景，重新对比（对应柯验《数值三方对账》§6 ②「改实验设计」）。

**柯验 §6 与本节的接缝**：柯验 ② 改实验设计里的「重新整定基线」正是为了满足何疑的条件 a——基线没整定过，柯验的数值可能对、但结论仍无效，两人在这一步会合。何疑处置改完后，涉及的数字要重新过柯验的三方对账。

## 数学基础章节规则

课程设有独立的"数学基础"章节（`content/math/`），与其他所有章节正交，供所有章节交叉引用。

**规则**：在编写任何课程内容时，如果遇到需要较多篇幅解释的数学概念（如复数、线性代数、微分方程等），且该概念不属于当前课程的核心主题，则：

1. 不在原地展开完整讲解，而是用一两句话交代直觉含义，然后引用数学基础章节的对应课程
2. 在 `content/math/` 下新建或引用已有的课程，以"假设读者只有高中数学水平"为起点编写。**这条规则由岳自检验**：他是唯一没有大学数学的角色，math 章 16 课每课必到；他说"从第 N 行开始跟不上"就是可判定的返工依据，缺席则郑核不得签发该章课程
3. 引用格式：`> 📐 本文用到了复数的基本概念，详见 [复数基础](/math/complex-numbers)。`

这样做的目的是保持每篇课程的聚焦性，同时让数学基础薄弱的读者有完整的补课路径。
