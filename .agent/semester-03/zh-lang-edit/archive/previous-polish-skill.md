# 逐课润色

读学期3计划、全局checklist的润色队列、[共同流程](../wiki-discussion/references/semester-03-core.md)、[语言规则](../wiki-discussion/references/language-review.md)及沈读记忆。一次只做一课；CLASSIC-01试点后的队列须等用户确认，不自动推进。

1. Phase1：审计整课与实际界面，保存原稿与来源hash；明确初学者起点、主线、选读和保留资产。列“原句/读者会卡在哪/改法”，不要从同义词替换开始。
2. Phase2三轮：文简改稿；学生指出具体理解断点；改完重读。术语首次解释、每段目的与章节过渡都要核。把过程说明放日志，把不必第一遍学的材料标选读；公式/定理必要条件仍须贴近结论。
3. Phase3：教授/柯验检查语义、数学、代码和参数未被润色偷改；沿用六组审校，沈读在体验组完整顺读终稿，按顺序记录首次出现的概念、拦截项和修改。完整终稿后才追加记忆（hash/已学/未学）。保留原课日志，新增润色日志。
4. Phase4：技术与语言放行分列；实验原代码执行、页面/公式/旧锚点、构建等仍按共同流程验收。若正文改变，更新浏览器Python源指纹前必须原始实验实跑。数学/代码/默认参数若有实质变化，转重构范围并补相关独立数值对账。全局润色行与原生产完成行分开，用户确认列只由明确反馈更新。

日志保留Phase1–4、A.1原六列逐量对账/A.2实测、B原九门槛与四补充、C比较、D改动去向，另附沈读顺读表与终稿记忆。日常提交推送master，Pages另授权。试点可交付“待用户精读”的版本，不能把角色放行记为用户通过。
