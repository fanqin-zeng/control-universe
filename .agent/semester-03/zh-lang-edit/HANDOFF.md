## 5. 每课工作流程

1. **读全文** + 按 POLISH-RULES 通读改写（先改写，后扫描）。
2. **标准扫描**（grep，命中后逐条人工分类为"编辑/登记/保留"）：
   `已交付|未交付|主例|2026-10|本书|旧稿|旧题|保留|原实验|滑块|拖动|试把|上一章|这一章|两章|本章|先看.*再看|读定义|读表|阅读时`；行首点小数 `(^|[^0-9a-zA-Z_.])[.][0-9]`（排除代码层）；直引号（prose 层属登记同族）。
3. **数值独立复算**：sympy 符号恒等式 + 与 notebook 不同的独立积分/求解；脚本放系统临时目录随用随弃；脚本自错如实记入记录（历课均有，从未发现课文数值错误之外的需改项）。
4. **记录** `records/<ID>.md`：重做结论 / 技术资产与检查（含实际命令与退出码）/ 待确认问题（登记项）/ 合入回执（留空）。
5. **PLAN** 对应行：状态→待合入，记录列→`[润色记录](records/<ID>.md)`。
6. **验收**：`npm run check` 退出 0（基线 PASS 21 · WARN 2）；起 dev server（端口 8080）→ 页面 HTTP 200 → `npm run verify -- <章>/<课>` → 杀服务器。

## 8. 环境与坑（Windows / Git Bash）

- **终端中文乱码是显示层**：Git Bash 提交输出可能乱码；验证提交信息用 `python -c` 读 `git log --format=%s` 做 UTF-8 断言（本分支历次提交均已验证无损）。
- **dev server 端口 8080**：`npm run dev` 启动（后台），verify 需要它；完成后 `netstat -ano | grep :8080` 找 PID `taskkill //F //PID`。
- **PLAN.md 合并冲突**：本分支与 master 都改行状态。历次解法：行 1–50 以本分支为准（润色进度权威），master 新交付行取 master（已完成/待润色）。若再合并 master，沿用"我的润色状态行保留、master 新增交付行照收"。
- **git**：禁 force-push、禁改写已推送历史；提交信息有历史笔误就保留（如 0f9eada）。
- **verify 分级**：A=0 FAIL 0 WARN；B=WARN 需在记录中登记（NONLINEAR-08 的习题标记形态 WARN、NONLINEAR-01/02 的前向链接 WARN 均属检查器口径，非正文错误）。
- **复算脚本常见坑**（sympy/scipy）：`Matrix.exp()` 在 s=1 求值，符号流用 `(A*s).exp()`；`sp.Rational(-5,-5)` 规范化为 +1；positive 假设会丢负根；solve_ivp 事件函数签名与积分器 dt 必须整除周期；标量符号没有 `.T`。
