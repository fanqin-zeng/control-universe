## §1. 模型B到底做错了什么（根因诊断）

模型B的失败**不是"编辑数太少"或"扫描不够仔细"**。旧HANDOFF把问题框架定为"零编辑课需要重新扫描"，这个框架本身就是错的。

**真正的根因：模型B把润色当成了模式匹配任务。**

具体表现：

1. **grep驱动而非阅读驱动**。模型B的工作流是：读POLISH-RULES → 提取出一组违禁模式（"旧稿""保留""先看…再看""滑块""拖动"等）→ 对每课跑grep → 命中则改、未命中则宣布"零编辑通过"。这把"润色"降维成了"查找替换"。
2. **编辑数成了质量指标**。模型B在每课记录里汇报"编辑数"（0处、1处、2处……），好像编辑数>0就代表做了工作。但一篇2148行的课文（NONLINEAR-07）只找到0处编辑，这本身就说明方法有问题——任何长文都不可能完美到不需要任何语言改进。
3. **"亮点保留"是自我安慰，不是质量证据**。模型B在每课记录里列出一堆"亮点保留"（"恒温器引入写得好""反步法步步可跟"），但这些只是模型B觉得写得还行的句子，**不等于它把整篇课文作为读者通读了一遍**。
4. **技术验收掩盖语言问题**。模型B花了大量精力做数值复算（sympy符号验证、独立RK4复算……），每课记录里堆满复算细节。技术验收是必要的，但它和语言质量是两回事——数值全对不代表中文读起来像人话。
5. **对"零编辑"的辩护暴露了思维定式**。模型B在旧HANDOFF里说"后期课程可能是生产侧已按母语标准写作，所以零编辑合理"。这把问题归因于外部（生产侧写得好），而不是反思自己的方法是否有盲区。

**一句话总结：模型B从未真正作为读者通读课文。它做的是"扫描→匹配→报告"，不是"阅读→理解→重写"。**

## §2. 正确的润色是什么

POLISH-RULES.md已经写得很清楚，但模型B实际上没有执行它的总原则。我把总原则提炼为一条判断标准：

> **把每个句子读出声，问自己：一个中文母语者讲课的时候，会不会这么说？**

如果答案是否，就重写。不是因为命中了某个grep模式，而是因为它**读起来不像人话**。

用户批阅里的典型问题（这些才是真正要抓的东西）：

- **翻译腔**："车是'开'的，不是'走'的"；"速度表则告诉你"没人这么说
- **回答读者没问的问题**：前文没提公式就说"先不用管公式"；讲导数时突然提"不模拟测量噪声"
- **复述图面/组件已展示的内容**：读者看得见蓝线绿线，不用你再写一遍"蓝线记录位置，绿线记录速度"
- **抽象举例等于没举例**：说"比如"就要给具体数字，不能只给抽象描述
- **没有信息量的句子**："微积分研究的正是这两件事……它们并非互不相干"——删掉读者什么都不缺
- **俯视读者**："s(2)不是s乘以2"——把读者当小学生
- **替读者规划路径**："你可以先学……再接着学"——教好你该教的，读者自己决定怎么学
- **术语首次出现不解释**："差商"裸用、"局部近似"凭空冒出
- **免责声明而非邀请**："Python用来核对结果，不是必学内容"→ 应该给人入口，不是划界限

这些问题的共性是：**写作者没有站在读者的角度想过"读者读到这句话时在想什么"。** 这不是grep能抓的。

## §4. 我的工作方法

### 4.1 每课流程

1. **通读全文**（不是扫描，是读）。作为第一次学这篇课文的读者，逐段读，遇到读着别扭的句子就标记。
2. **重写不合格的句子**。按POLISH-RULES的八条硬规矩，核心是"读出声像不像人话"。
3. **检查首次术语/符号**。每个新概念在首次出现处是否已解释？是否用后文解释来搪塞前文的缺失？
4. **检查举例是否具体**。说"比如"的地方是否给了具体数字？
5. **删除无功能句子**。复述图面的、回答无人问的问题的、信息量为零的。
6. **技术验收**：`npm run check` 退出0；起dev server → `npm run verify -- <chapter>/<lesson>`。不改公式、数值、notebook代码、组件默认值、H2结构、锚点。
7. **记录**：`records/<ID>.md` 写明实际改动与理由，不汇报"编辑数"，不列"亮点保留"充篇幅。

### 4.2 与模型B方法的根本区别

| | 模型B | 我 |
|---|---|---|
| 驱动力 | grep模式匹配 | 通读全文 |
| 质量指标 | 编辑数 | 读出声是否像人话 |
| "零编辑"的含义 | 方法跑完没命中 | 通读后确实找不到需要改的 |
| 记录重心 | 复算细节 + 亮点列表 | 实际改了什么、为什么改 |
| 对技术验收的定位 | 与语言质量并列的证据 | 必要但独立的底线 |

### 4.3 硬约束（继承自README，不重复展开）

- 不改公式、数值、notebook代码与打印串、组件默认值、H2/H3结构、锚点

**何时更新**：
- 用户提出新的润色要求或纠正我的做法 → 立即记录
- 润色中遇到典型问题并做出判断 → 记录

**记忆不记什么**：
- 不记技术验收细节（数值复算、check/verify结果）
- 不记课程具体内容（那是课文本身的事）
