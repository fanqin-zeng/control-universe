# Fix Log 013 - JupyterNotebook 的 setupCode 收尾不能带逗号（JSX 属性间逗号非法）

**Date**: 2026-09-24  
**Documents**: `content/intelligent/fuzzy-control-basics.mdx`（影响所有手写 `<JupyterNotebook>` 的课程）  
**Type**: BUG (Negative case)  
**Summary**: `setupCode={`...`},` 这种"收尾带逗号"的写法在 JSX 里非法（属性之间只能用空白分隔），next-mdx-remote 编译直接抛错、`getLesson` throw、页面 404；本地 Python harness 只执行 cell 代码、完全不解析 MDX，因此抓不到

## Problem

重写后的 `intelligent/fuzzy-control-basics` 在浏览器里 404（"This page could not be found"），而同章节其它课程正常。dev 日志里是：

```
[next-mdx-remote] error compiling MDX:
Unexpected character `,` (U+002C) before attribute name, expected a character
that can start an attribute name ...
  > 575 | TH0, W0 = 5 * DEG, 10 * DEG`},
```

`app/(wiki)/[chapter]/[lesson]/page.tsx` 里 `getLesson` 抛错即 `notFound()`，所以 MDX 编译失败的表现是 404 而不是 500——这会让排查方向完全跑偏（先怀疑路由/缓存，而不是内容）。

## Root Cause

JSX 元素的属性序列只允许用空白分隔：

```mdx
<JupyterNotebook
  title="..."
  setupCode={`...`}      ← 这里不能有逗号
  cells={[ ... ]}
/>
```

写成 `` setupCode={`...`}, `` 时，MDX 的 JSX 解析器在表达式容器闭合后期待"下一个属性名或 `>`"，却遇到 `,`，整篇编译失败。

本次 9 个 notebook 里有 8 个带这个逗号（从旧稿复制的写法）。它之所以能长期潜伏：

1. 本地 notebook harness（提取 setupCode/cells 后交给内核执行）对 MDX 语法无感，逗号被当成普通文本跳过；
2. `npx tsc --noEmit` 不检查 .mdx；
3. 只有真正请求页面、触发 next-mdx-remote 编译时才暴露。

## Fix

1. 全文替换 `` `},\n  cells={[ `` → `` `}\n  cells={[ ``（本次 8 处）；
2. 把"浏览器端到端验证"列为交付的硬门槛：页面必须 200 且 `h2 数 == catalog 小节数`。只要 MDX 编译失败，这条断言立刻报警（404 页只有 1 个 h2）；
3. 排查 404 时先看 `logs/dev.log` 的 `MDX 编译失败` 记录——本项目的 404 很可能是内容编译错误，不是路由问题。

## Verification

- 修复后 `GET /intelligent/fuzzy-control-basics` 200，12 个 H2 与 catalog 完全一致，katex-error 0；
- 9 个 notebook 全部运行完成：18/18 张图、0 Traceback；
- `grep -c '\`},' content/**/*.mdx` 应为 0（可作为 CI 级检查）。
