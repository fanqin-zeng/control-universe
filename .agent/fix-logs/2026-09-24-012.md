# Fix Log 012 - MDX 多行 display math 必须让 `$$` 独占开/闭行

**Date**: 2026-09-24  
**Documents**: `content/nonlinear/backstepping.mdx`（影响所有使用多行 `$$...$$` 的课程页面）  
**Type**: BUG (Negative case)  
**Summary**: 多行 display math 若把内容写在开/闭 `$$` 同一行（如 `$$\begin{aligned}` 或 `\end{aligned}$$`），remark-math 会吞掉首行内容或整块不闭合，导致后续整篇文章被当成一个数学块、以 KaTeX 错误原文形式渲染

## Problem

重写后的 `nonlinear/backstepping` 页面在浏览器里只渲染出 2 个 H2（引言、严格反馈系统），其后所有正文（表格、notebook、交互组件、习题答案）全部消失；`document.body.innerText` 却包含全文，且这些文字以**未渲染的 LaTeX 源码**形式出现（如 `$$\lvert\Delta u\rvert\le...$$` 原样显示）。

DOM 检查发现这些内容位于 `span.katex-error > div.math > article` 内：即从 §2 的第一个 display math 开始，**整篇文章被解析成了一个数学块**。KaTeX 报错的源码里还缺了首行（`\begin{aligned}` 不见了），说明开 fence 同行的内容被丢弃。

## Root Cause

本项目数学管线是 `remark-math` + `rehype-katex`（`lib/content.ts`）。在 MDX 编译下，flow math 的 fence 规则要求：

- 开 fence `$$` **独占一行**（同行后续内容会被丢弃）；
- 闭 fence `$$` **独占一行**（写在内容行尾如 `\end{aligned}$$` 不会闭合块）。

旧课程（如 `feedback-linearization`）的多行公式全部是

```mdx
$$
\dot{x} = f(x) + g(x)u, \qquad y = h(x)
$$
```

所以从未暴露。本次重写引入了 19 处 `$$\begin{aligned}` / `\end{aligned}$$` 写法，第一处（§2 定义块）就让其后全文落入未闭合的数学块。

注意单行公式 `$$...$$`（开闭在同一行）是合法的，不受影响——这也是该 bug 容易被漏检的原因：页面"大部分公式看起来是好的"。

## Fix

脚本化规范化 `content/nonlinear/backstepping.mdx`（两步，各 19 处）：

1. 行尾闭合：`<content>$$`（且该行不以 `$$` 开头）→ 拆成 `<content>` + 独立一行 `$$`；
2. 行首带内容：`$$<content>`（且该行不以 `$$` 结尾）→ 拆成独立一行 `$$` + `<content>`。

规范化后全文件 83 个 `$$` 开/闭行配对平衡（parity 扫描确认 final state = closed）。

## Verification

页面 `http://localhost:8080/nonlinear/backstepping`：

1. 修复前：`h2` 只有 2 个、`.katex-error` 若干、交互组件与 notebook 按钮数为 0。
2. 修复后：`h2` = 12（与 catalog subsections 逐字一致）、`.katex-error` = 0、3 滑块 + 6 个"▶ 全部运行"按钮 + 2 个 ECharts canvas 全部出现。
3. 6 个 notebook 同时"全部运行"无 Traceback，各出 1 张图；控制台无 React 告警。

## Lessons Learned

- **正案例**：多行 display math 一律写成"开 `$$` 独占一行 / 内容 / 闭 `$$` 独占一行"；单行公式才允许 `$$...$$` 同行。
- **负案例**：不要以"本地 Python 跑通 + 文本 grep 通过"作为 MDX 的验收标准——数学 fence 这类**渲染期**错误只有浏览器能发现。本课的验收清单因此必须包含"`h2` 数量 == catalog 小节数"与"`.katex-error` 数量 == 0"两条 DOM 断言。
- **诊断技巧**：当"innerText 有全文但 DOM 里没有对应标题/组件"时，先查内容是否被吞进了某个错误节点（`katex-error`、`pre`、`code`），而不是怀疑 SSR 截断或流式渲染未完成。
- 该校验已并入后续课程的浏览器验证步骤（见 `docs/discuss-log/course-01/07-nonlinear/07-backstepping.md` 附录 C）。
