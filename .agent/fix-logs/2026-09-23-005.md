# 修复摘要：四个交互组件违反Fix-002（动态坐标轴）

## 问题（负案例）

在v1.3重构完成后的fix-logs审查中发现，四个新创建的React交互组件违反了**Fix-002设计规则**（固定坐标轴范围），导致用户拖动参数时曲线看似不动、只有坐标轴缩放。

**违规组件及位置**：

1. **`step-bode-explorer.tsx`** (Line 57, 73)
   ```typescript
   const tEnd = Math.max(3, 15 / wn);  // 动态计算！
   ...
   max: tEnd,  // xAxis随ωn变化
   ```
   当用户拖动ωn滑块（0.5~20）时，tEnd从0.75变到30，阶跃响应曲线在视觉上几乎不动，因为坐标轴跟着缩放了。

2. **`impulse-explorer.tsx`** (Line 47-52, 69)
   ```typescript
   const yMax = useMemo(() => { ... return Math.max(2, max * 1.2); }, [curveData]);
   ...
   min: -yMax, max: yMax,  // yAxis动态重算
   ```
   当ζ改变时，yAxis根据峰值重新缩放，曲线看起来"自适应填满画布"而非在固定参考系中移动。

3. **`suspension-time-explorer.tsx`** (Line 89)
   ```typescript
   max: Math.max(1.5, peakY * 1.1),  // yAxis动态
   ```
   同样的问题——yAxis随超调量变化，无法直观看到参数对响应幅值的影响。

4. **`pole-zero-explorer.tsx`** (Line 46-47, 55-56, 63-64)
   ```typescript
   const xRange = wn * 2;   // Dynamic!
   const yRange = wn * 1.5; // Dynamic!
   ...
   min: -xRange, max: xRange,  // xAxis scales with ωn
   min: -yRange, max: yRange,  // yAxis scales with ωn
   ```
   当用户拖动ωn滑块（1.0~15.0）时，s平面的x和y轴同时按比例缩放，极点在视觉上几乎不动。这是最严重的Fix-002违规，因为两个轴都在动。

## 根因分析

Fix-002的教训（"固定参考系 + 移动目标"优于"动态缩放 + 目标不动"）**未被充分传达**到新组件的开发中：
- ✅ 所有9个组件都正确设置了`animation: false`（Fix-003合规）
- ❌ 只有`FirstOrderStepExplorer`使用了固定xAxis（`max: 30`）
- ❌ 三个新组件仍使用`Math.max()`动态计算坐标轴范围

**为什么会漏掉**：v1.3-refactor SKILL的模板中`max: 10`只是一个占位符，没有明确警告禁止使用`Math.max()`或动态计算。开发者需要理解Fix-002背后的交互设计原则：**稳定的坐标系让用户看到"什么在变"，而不是"什么都跟着变"**。

## 经验提炼

1. **Fix-002规则应写入SKILL模板**：v1.3-refactor的React组件模板中，`max: 10`旁边应添加注释："必须是常量，禁止Math.max()/Math.min()等动态计算"
2. **坐标轴固定的物理意义**：
   - xAxis固定：让用户看到"响应速度变化"（T/3T/4T标注线在时间轴上移动）
   - yAxis固定：让用户看到"幅值变化"（超调量高低在垂直方向上的差异）
3. **何时可以动态**：只有在数据范围完全不可预测（如用户输入任意传递函数）时才考虑动态yAxis，且应在文档中说明理由
4. **构建验证不够**：`npm run build`只检查语法和类型，不检查交互设计模式。需要在SKILL中加入fix-logs审查步骤（已在2026-09-23完成SKILL更新）
