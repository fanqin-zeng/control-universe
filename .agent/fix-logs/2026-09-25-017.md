# Fix Log 017 - 拼接脚本给 cell 首行多加一个 `%`，被 IPython 当成 line magic

**Date**: 2026-09-25  
**Documents**: `content/nonlinear/nonlinear-characteristics.mdx`（全部 9 个 JupyterNotebook）  
**Type**: BUG (Negative case: 页面能打开、组件能初始化，但一运行就报 `UsageError: Line magic function '%#' not found`)  
**Summary**: 用脚本把内核验证过的 harness cell 代码"逐字拼接"进 MDX 时，占位符写成 `%%NBn%%` 并经过了 `%` 风格替换，结果每个 cell 的首行从 `# 注释` 变成 `%# 注释`。IPython 把行首 `%` 当 magic，整格直接失败——而本地 harness 里同样的代码是好的，因为 harness 没经过这层替换

## Problem

课程页 `/nonlinear/nonlinear-characteristics` 返回 200，9 个 Notebook 全部正常初始化（`In []:`），点"运行"后第一格输出：

```
UsageError: Line magic function `%#` not found.
```

9 个 Notebook 全都一样。而 `.agent/nc-harness6.py` / `nc-harness8.py` 在内核上跑同一批 cell 时全部通过并产出了正文引用的所有数字。

## Root Cause

MDX 里的占位符是 `%%NB1%%` … `%%NB9%%`（写两个 `%` 本意是"转义"）。拼接脚本在替换前对模板做了一次 `%` 格式化，`%%` 被折叠成 `%`，于是 `{ code: \`%%NB1%%\` }` 变成 `{ code: \`%NB1%\` }`；紧接着把 `NB1` 替换成 cell 代码（首行是 `# 叠加原理的定量破坏…`），得到 `{ code: \`%# 叠加原理…\` }`。

Python 的 `#` 注释和 IPython 的 magic 都以行首字符判类型，`%#` 于是被解析成名为 `#` 的 line magic。

## Fix

把 9 处 `` { code: `%# `` 改回 `` { code: `# ``。补一个校验脚本 `.agent/nc-verify.py`：用 `importlib` 加载 harness、取出 `CELLS`，再用 `re.findall(r"\{ code: `(.*?)` \}", src, re.S)` 从 MDX 抽回 cell，逐格 `==` 比对（不是"看起来一样"，是字符串全等），同时断言无反斜杠/反引号/`${`。结果：9/9 `ALL MATCH`。

## Verification

- `.agent/nc-verify.py`：`cells found in MDX: 9`，NB1…NB9 全部 `OK`，末行 `ALL MATCH`。
- 浏览器实跑 9 个 Notebook（`▶ 运行`），全部 `In [✓]`、各出 1 张图（`naturalWidth !== 0`），无 `UsageError`。
- 抽查数值与 harness 逐位一致：NB1 残差 `1.010303e-14` / `8.032953e+01%`、齐次性比值 `2.000000` / `1.163721`；NB4 基波 `1.150000000000`、饱和 THD `23.2900%` / `35.4169%`；NB8 三种模式超调 `21.052%` / `80.181%` / `2.254%`；NB9 吸引域 `c in [0.500, 1.500]`。

## Rule

**"逐字拼接"必须有逐字校验。** 只要 cell 代码经过任何一层字符串格式化（`%`、`.format`、f-string、模板引擎），就要用一个独立脚本把 MDX 里的 cell 抽回来和源做全等比对，并把这一步列为交付门槛。占位符不要用 `%%` 这种"看起来是转义"的写法——用 `<<NB1>>` 之类不会被任何格式化层解释的记号。

行首 `%` 在 IPython 里永远是 magic：Python 注释、shell 提示符、LaTeX 注释混进 cell 首行都会静默改变语义。
