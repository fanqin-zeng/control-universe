# Fix Log 014 - 交互组件的默认参数与轨迹范围必须能复现正文的手算例

**Date**: 2026-09-25  
**Documents**: `components/wiki/nyquist-limit-cycle-explorer.tsx`（影响所有"组件 + 正文手算例"配对的课程）  
**Type**: BOTH (Negative case: 组件与正文互相打脸；Positive case: 覆盖性判据 + 默认值对齐)  
**Summary**: `NyquistLimitCycleExplorer` 的 $-1/N(A)$ 轨迹从 $A=1.05$ 起（为避开饱和在 $A\le1$ 的奇异），继电器分支也共用这个下限，导致默认参数下永远画不出正文手算例的交点（$A_0=4/(3\pi)=0.4244$）；交点检测又只用 Nyquist 的负实轴穿越点、不检查 $-1/N$ 轨迹是否覆盖该点，于是"不存在极限环"的参数也会误报交点

## Problem

重写 `nonlinear/describing-function` 时，正文手算例给的是理想继电器 $M=1$ 串 $G(s)=1/(s(s+1)(0.5s+1))$，谐波平衡解为 $G(j\sqrt2)=-1/3$、$A_0=4/(3\pi)=0.4244$。但把正文写完后去浏览器里核对交互组件，发现：

1. 默认非线性是"饱和"，而饱和的 $-1/N$ 轨迹只从 $-1/k=-1$ 向左，够不到 $-1/3$——面板上没有交点，读者拖动滑块也找不到正文说的那个点；
2. 即使切到"继电器"，轨迹的 $A$ 下限仍是 $1.05$（继电器 $-1/N=-\pi A/4\le-0.82$），交点依然画不出来；
3. 组件的交点检测只判断"Nyquist 曲线的虚部过零且实部为负"，把穿越点直接当成交点，**从不检查 $-1/N$ 轨迹是否真的经过那里**。于是"饱和 + $K=1$"这种描述函数判定不存在极限环的组合，也会弹出"预测的极限环"面板——这是会教错学生的假阳性；
4. 面板只显示"交点位置 $(-0.33,0)$"，不显示正文关心的 $A$ 与 $\omega$，读者无法把组件输出和手算结果对齐；
5. echarts 在 legend 里声明了条件性 series "交点"，无交点时控制台报 `交点 series not exists`。

## Root Cause

组件是早期按"饱和非线性"这一个场景写的：$A\le1$ 时饱和处于线性区、$N=k$、$-1/N$ 恒为 $-1/k$，为了避免除零把轨迹起点设在 $1.05$ 是合理的。后来加了继电器分支，却没有同步放开 $A$ 的下限——**继电器的 $N=4M/(\pi A)$ 在 $A\to0$ 时发散，轨迹从原点出发，本来就应该覆盖小振幅**。

交点检测的半条判据同源于此：只做了"线性侧"（$G$ 的实轴穿越），漏了"非线性侧"（$-1/N$ 轨迹的取值范围）。描述函数的交点条件本来就是两条曲线**同时**成立。

## Fix

1. 轨迹起点按非线性类型分开：继电器 $A\in[0.02,10]$、步长 $0.02$；饱和 $A\in[1.05,10]$、步长 $0.1$（保留 $A\le1.01$ 的保护返回）；
2. 默认 `nonlinearityType` 改为 `"relay"`，与正文手算例一致；
3. 交点检测加**覆盖性判据**：$-1/N$ 轨迹随 $A$ 单调递减且趋于 $-\infty$，所以只有当 Nyquist 穿越点 $\le$ 轨迹起点时才有交点；成立时用 60 步二分反解 $A$、用网格比例插值反解 $\omega$，不成立时清空交点并显示"无交点"面板（附原因：饱和 $N\le k$ / 继电器轨迹从原点向左）；
4. `legend.data` 随 `hasIntersection` 变化，消除 echarts 警告；
5. 面板文案升级为"振幅 $A$ / 频率 $\omega$ / $f$ / 交点位置"，与正文的量一一对应；样式改为行内 style（Tailwind 在 Windows 上不可靠）。

## Verification

浏览器实测（`GET /nonlinear/describing-function` 200，12 个 H2 == catalog，katex-error 0）：

- 默认（继电器，$K=1$、$T_1=1$、$T_2=0.5$）：面板显示 $A=0.4241$、$\omega=1.4151$ rad/s、交点 $(-0.333,0)$；手算 $0.4244$ / $1.4142$，差异来自组件 $0.05$ rad/s 的 $\omega$ 网格（已在正文图注中写明）；
- $K$ 拉到 $2$：$A=0.8482$、交点 $(-0.666,0)$；手算 $8/(3\pi)=0.8488$；
- 切"饱和"（$K=2$）：显示"无交点"面板（穿越点 $-0.666$ 在轨迹起点 $-1.013$ 右侧）——与正文案例 2 的 $K<3$ 不振荡一致；
- `DescribingFunctionExplorer` 联动性：$k$ 从 $2$ 改回 $1$ 并把类型从"饱和"切到"理想继电器"后，canvas 像素校验和 $461217\to475040$，第二个滑块按类型正确显隐（`M (relay level)`）；
- 控制台只剩 React DevTools 的 info，`交点 series not exists` 警告消失。

## Rule

**交互组件必须复现正文的手算例**：默认参数取正文算例的参数，控件范围要覆盖正文出现过的全部数值，组件的结论性输出（交点/稳定/无解）必须做完整判据。写完全文后要在浏览器里把手算例的数字在组件上"点"一遍——组件与正文对不上时，读者会认为其中一个是错的，而通常错的是组件。
